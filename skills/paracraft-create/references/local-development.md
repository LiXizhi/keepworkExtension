# Local Paracraft development checks

Use this page when changing or diagnosing the integration. For ordinary creation use [Web authoring](aichat-web.md). The full operator guide with runnable probes, test prompts and original screenshots lives in the ParaWorld repository at `docs/aries/paracraft-cli-dev/README.md`.

1. Identify the checkouts and record upstream HEAD and local modifications. Start Keepwork MCP from its checkout with `npm run dev:server --prefix apps/vscode-extension`. The watcher rebuilds TypeScript and restarts its daemon. Its development process reads `skills/paracraft-create` directly on each request. Installed builds read their packaged skill. Compare `GET /paracraft/authoring` with the edited reference and check the changed schema. A fresh skill read or a new conversation picks up the new guidance.
2. For desktop, use ParaWorld's `bin/paracraft-cli-530.bat --new-instance` if a suitable client is unavailable. Read health on the registered native port, then exercise the changed method using `run_npl_code` and read `tail_log`. Use a writable test world for changes. Select the intended clientId throughout.
3. For Web, start the webparacraft checkout's **Serve WebParaCraft (8088)** task. Load `/npl/webparacraft/keepwork/local.html` with `searchroot` pointing to the ParaWorld checkout, `searchpath=script/` and `mcp=http://127.0.0.1:8089`. Verify that the served engine resources and the overlay file from `/fs/file` match disk. The overlay caches each attempted path for the lifetime of the engine. For fresh startup code recreate the iframe. For a live test module, refresh its MEMFS bytes from the checkout, then force-load it and call its changed function on this same client.
4. For end-to-end acceptance, use the apps checkout's Live Server and open `http://127.0.0.1:3000/official/apps/tools/AIChat/AIChat.html?dev=true&chat=new&tool=paracraft&frontpage=hide`. Inspect the actual engine iframe origin, overlay query and entry receipt. Keepwork with keepwork-pro uses the main conversation tool catalog. External Codex CLI uses the conversation-bound MCP catalog; check the exact CLI model and reasoning effort. Both paths should access the same server-owned skill and selected world.
5. Enter only the creative goal in a fresh Composer conversation. Record tool calls, world identity, block readback, the world-local BMax filename, running CodeBlocks, behavior samples, the actual returned image and time to delivery. For a follower compare its trace to the leader in the same frames using `sample_actor(relativeTo=...)`. Change the subject and movement rule in another case to exercise composition. Keep authored coordinates and programs out of the skill and the test prompt.
