# 交互、角色与小游戏的组合设计

先读 [code-blocks.md](code-blocks.md) 以建立真实演员、事件生命周期与编辑流程。下面是可迁移的设计模式；按任务推导状态和输入，不把所有玩法塞进固定模板。来源与重新定位方式见 [codeblock-lessons.md](codeblock-lessons.md)。

## 角色行为

| 需求 | 从教学提炼的做法 | 增加的边界与验收 |
|---|---|---|
| 点击说话/打招呼 | F1 04、13；点击或近距离按键提出对话请求；worker 负责 `say/anim/play` | 连续点击不会中断后永久卡住；对话结束回 idle；动作 ID 必须存在于模型 |
| 可选择的 NPC 对话 | F1 05；530 `(19214,5,19188)` 的文字/按钮 `ask` | `local choice=ask(...)`，取消不算答错或完成；一次仅一个对话框；离开/停止清理自己的 UI |
| 伴随宠物 | F1 14–16；朝向目标，距离大才靠近，近时等待 | 进入跟随/停下使用不同阈值，减少边界抖动；无目标、障碍、离开区域时有明确策略 |
| 巡逻/追逐/等待 | F1 02、07、12 与 530 状态切换 | 单一运动循环，事件只切状态；用小步或可取消动作，规定响应时间；随机行走限制活动范围 |
| 双人协作表演 | F1 08、10、15；广播、命名角色与并行运动 | 一个位置通道由一个模块控制；消息带场景前缀；等候广播不能含永久循环 |
| 升降台/坐骑/挂接 | F1 24、530 `(19211,5,19253)` | 分别定义停站、上车、运行、下车；仅停站允许上/下；按键、停止和异常退出均解除自己的挂接 |
| 动画机关 | F1 18、19、40；`play`、`playLoop` 驱动已有电影片段 | 确认毫秒区间与骨骼、方向；动画驱动物体与碰撞通道分别检查，外观打开不代表可通行 |

跟随玩家的最小 actor-bound 程序（非寻路器）：

```lua
local following=false;
while true do
    local d=distanceTo("@p");
    if d>4 and d<30 then following=true end
    if d<2 or d>=30 then following=false end
    if following then
        turnTo("@p");
        walkForward(0.25,0.1,true);
    end
    wait(0.1);
end
```

第三个参数 `true` 让小数步长使用精确行走目标；默认行走会取整，小步可能不动。30 是这个设计的活动距离，不是 API 限制；不要在任意远处循环传送到玩家。跟随命名演员时先确认目标存在；`@p` 是当前玩家的特殊选择器，`getActor("@p")` 返回其玩家演员，和查找普通演员名字的路径不同。

### 事件提出请求，worker 执行长任务

这是重复点击和带等待动作的通用结构。请求布尔值表示合并重复点击；若需求是逐个执行，使用有上限的队列。长动作内需响应取消时，拆成小段并检查轮次/状态。

```lua
local pending=false;
registerClickEvent(function() pending=true end);
while true do
    if pending then
        pending=false;
        local choice=ask(L"需要帮助吗？",{L"介绍玩法",L"暂时不用"});
        if choice==1 then say(L"点击蓝色目标即可收集。",2) end
        -- 当前对话期间的连点合并丢弃，不连续弹出对话。
        pending=false;
    end
    wait(0.1);
end
```

若要在对话过程中运行背景巡逻，分别分配朝向/移动/说话责任；不要让巡逻不断覆盖对话时的朝向。`run` 能并行，但不是避免属性竞争的办法。

## 可组合的小玩法

| 玩法 | 状态、模块与关键接口 | 至少要跑通的场景 |
|---|---|---|
| 点击收集/打靶 | 控制器持有 phase/epoch/score/hits/deadline，克隆携带 id/epoch；触发后先登记命中，再反馈 | 同一目标连点只计一次；胜利后不再计分；失败清除对象；连续重开无残留 |
| 倒计时竞速/躲避 | ready → running → won/lost；当前时间减起始时间；检查点保存合法进度 | 超时优先级、出生无敌、碰撞冷却、顺序检查点、越界回退和重开 |
| 对话答题 | 题库、当前题、得分、dialogBusy；按钮索引/输入答案转换；统一题目 owner | 正误、取消、重复确认、全部题目结束、重置；答题取消不意外加分 |
| 多机关解谜 | 记录每个 puzzleId 是否完成；所有条件满足再执行一次开门；Reset 清除历史 | A→B 与 B→A、重复 A、只完成部分、开门中重置、再玩；动作不累计漂移 |
| 感应自动门 | F1 30 的距离滞回：例如小于 4 打开，大于 7 关闭 | 门停留 open 期间不重复位移；关闭位置取初始锚点；角色真实可通过 |
| 密码锁+电路 | F1 33、530 密码输出；判对后 `setOutput(15)`，复位/失败时输出 0 | 取消/错误不打开；中继器真实读到信号；断电与再启动按预期；软件密码不是安全认证 |
| 音效/音乐装置 | F1 34、38；输入改变有界曲目索引，单一音轨负责人 | 首尾环绕、快速连点、停止自己音轨；不无条件关闭全世界背景音 |
| 棋盘游戏 | 棋盘数据与显示分离；放置 → 判胜/和 → 切回合；克隆只是棋子视图 | 越界/占用拒绝；四方向连线；终局禁落子；和局；轮次重置清克隆 |
| 角色碰撞小游戏 | F1 12、530 碰撞组例；配置 physicsRadius/Height、groupId；选择轮询或碰撞事件 | 静止持续接触不重复扣血；速度过快不穿透；克隆/组过滤正确；边界和复活 |
| 计时/旋转景观 | F1 03、09、10、21；有限克隆寿命、绝对时间计算角度、不同通道组合 | 长时间数量有上限；暂停与重置归位；低帧率速度仍一致 |

碰撞事件要先确认触发链。530 的 `dog` 例子每步显式 `broadcastCollision()`，另一个角色监听名字或组号；仅注册回调不证明普通脚本位移一定触发所需碰撞。`moveForward`+`isTouching` 的大步也可能越过障碍。根据角色尺寸和速度缩小步长或采用原生物理行走/扫掠检查。

## 完整示例的可改点

[codeblock-playground.lua](../examples/codeblock-playground.lua) 同时演示物理搭建、克隆生命周期、轮次状态、得分去重、自然超时、广播清理和 NPC 状态切换。

- `roundSeconds` 与 `targetCount` 决定规则；增加目标数量时同步改变生成区域、间隔和场地尺寸，避免超过场地或重叠。
- 目标回调只写按目标 ID 去重的 `hitRequests`，控制器用自己的时钟检查 deadline 后统一计分；截止时优先失败。不同物理代码块的 `getTimer()` 起点不同，不能在目标回调直接拿其本地时间与主持人的 deadline 比较。显示隐藏等待命中确认，不能把点击反馈当作已接受计分。
- 把目标点击改为距离/接触判定，可以做收集寻宝；只保留一个计分入口与命中表，不让点击和碰撞各加一次分。
- 把目标的 `id` 改为题目/机关 ID，可以做解谜；判定条件换为完成集合；反馈换为门动画和灯。不要复用收集游戏的“马上删除”语义给仍需显示完成状态的机关。
- 主持人初始化共享表，跨重新上电保持 epoch 递增，目标保存 `epoch`，结束后异步广播清理，tick 还处理主持人单独断电。清理回调复查当前轮次，迟到的清理事件不删新一局对象。例子不等待可能已停机的接收器；0.1 秒让清理有机会执行，不把该延时当作成功确认。事件监听可能对所有克隆执行，所以 spawn/reset 等处理必须区分模板与实例。
- 修改 NPC 的目标、状态或巡逻点时，保留一个位置写入者；需要真实障碍导航则改行走控制并验证，不把示例的位移巡逻称为避障。

## 从 530 棋盘迁移到任意 N 连子

530 把棋盘/输入/黑白克隆/裁判/终局拆成六个职责。可以保留这种模块划分，但迁移时补足该教学源未完整处理的终局锁、和局、快速输入、启动时序和重置竞争。

推荐由单一 worker 顺序消费输入：校验 phase、整数坐标、1..size 范围和空位 → 写入 data → 检查胜/和 → 切换玩家 → 产生视图事件。先更新逻辑再 `clone/broadcast`，把 `{x,z,player,epoch}` 放消息里；不要像旧例那样用 `_G.new_x/new_z` 临时共享坐标让并发克隆读取。

下面是判胜的纯逻辑部件，不是完整游戏。`board["x,z"]` 存 `1/2`，`x,z` 为本次已放置的位置；函数检查穿过最后落子的双向连线，复用到井字棋/四子/五子棋：

```lua
local function hasLine(board,x,z,player,needed)
    local dirs={{1,0},{0,1},{1,1},{1,-1}};
    for _,d in ipairs(dirs) do
        local count=1;
        for _,sign in ipairs({-1,1}) do
            local k=1;
            while board[(x+d[1]*k*sign)..","..(z+d[2]*k*sign)]==player do
                count=count+1;k=k+1;
            end
        end
        if count>=needed then return true end
    end
    return false;
end
```

全盘已满且没连线则和局。Reset 递增 epoch，清空 board/step/input queue，向己方棋子发清理事件；旧 epoch 的迟到回调直接忽略。若用 `mousePickBlock`，必须核对棋盘区域和所点击的物体；若用按钮/按键，定义按下沿与长按策略，不能一帧放一颗。

迁移验收应改变规则而非只换颜色：例如把五目标限时收集改成“只收三种指定目标，误点扣时”，或把五子棋改成 4×4 三连。重新推导状态和测试组合，确认新规则成立，再做美术包装。联网游戏另需权威状态与网络协议，530 中的网络演示不构成多人同步实现。
