# KeepWork 家庭平板产品规划草案

日期：2026-10-12。阶段：产品方向探索，尚未冻结硬件、价格、排期与首发地区。

KeepWork 家庭平板面向家庭消费市场，让孩子通过语言学习探索世界，让老人通过人生几何记录和重访自己的人生，并通过 我的数字大脑（AIChat） 使用各自的第二大脑。同一台平板支持儿童和老人切换使用。2026-10-12 补充确定：围绕全家的第二大脑，以家庭登录 UI 进入孩子1、孩子2、老人1、老人2四个角色；每人只显示自己的数字世界（孩子为哈奇，老人为人生几何）、我的数字大脑（AIChat） 和个人日历。我的数字大脑（AIChat） 入口固定为 https://keepwork.com/chat。

## 已确定的方向

李西峙在 2026-10-12 本次讨论中明确：雄安正在规划 2C 平板；儿童和老人可以共用一台设备；包括出海；Launcher 只整合 我的数字大脑（AIChat）、魔法哈奇（语言学习）、人生几何；我们与 SilverMind 已有 Launcher 开发经验，现在需要规划自己的 KeepWork 家庭平板。

以下产品结构、实施顺序和试点指标为本草案建议，不代表已经批准立项或已经实现。品牌沿用 KeepWork；我的数字大脑（AIChat） 的对外展示名可沿用已确立的「KeepWork 第二大脑」，工程名称保留 我的数字大脑（AIChat）。[1]

## 用户与购买理由

主要使用者为儿童与老人，付费和设备管理者暂按家庭中的成年人设计。购买者与使用者可以不同，也可以是老人本人。

共同价值是“一台设备，家人各有自己的学习和记忆空间”。儿童侧用魔法哈奇形成持续语言练习，老人侧用人生几何形成持续讲述与回看，我的数字大脑（AIChat） 承接通用问答与个人记忆。三者需要各自成立；家庭联动增加价值，不作为单人能否使用的前提。

首批试点优先寻找同时有儿童和老人使用需求、能安排错峰使用的家庭。同时保留只给儿童或只给老人购买的路径，避免双人配置成为开箱门槛。试点须单独观察设备争用：如果儿童持续游戏挤占老人使用，后续允许同一家庭绑定第二台设备，不强迫共用。

## 三个应用的职责

| 应用 | 面向家庭的作用 | 首版要跑通的行为 |
| --- | --- | --- |
| 我的数字大脑（AIChat）／KeepWork 第二大脑 | 每位成员自己的 AI 助手，承接通用问答与个人资料 | 语音或文字提问，保存并找回自己的内容 |
| 魔法哈奇 | 儿童语言学习入口，利用角色、任务与情境促进练习 | 进入一个语言情境，听懂或表达一句话，获得反馈并保存进度 |
| 人生几何 | 老人人生档案入口，以回忆、照片与时空场景组织个人故事 | 讲一段经历，确认保存，之后能够回看、收听或继续补充 |

魔法哈奇已有多个产品分支。首版暂以带双语学习的「初心之旅」为候选入口，具体包和版本在接入前锁定，不混用 H5 宠物版与 3D 复刻线。[3]

人生几何采用独立 LifeStory 项目，不将 SilverMind 的「岁月留声」当成同一产品。[2] 家庭平板的老人侧围绕人生记录展开，不把 SilverMind 的测评、训练和老年大学自动扩入本次范围。

## Launcher 的使用方式

开机进入家庭登录，再选择孩子1、孩子2、老人1、老人2。每位成员进入自己的第二大脑空间，角色切换保持显眼且固定。

- 孩子1和孩子2：魔法哈奇数字世界、我的数字大脑（AIChat）、各自日历。
- 老人1和老人2：人生几何数字世界、我的数字大脑（AIChat）、各自日历；默认大字。
- 我的数字大脑（AIChat） 固定使用 `https://keepwork.com/chat`。
- 家庭管理员的付款、授权和设备管理仍属于后续正式账号设计。

个人日历显示月历和选中日期的安排。H5 原型支持按角色新增、修改和删除日程，仅保存在本机；正式产品再对接个人日历数据源。原型家庭登录不收集密码、不替代真实认证。

实际应用打开后，桌面按钮、应用名、身份提示、新标签页打开合并进平板最上面的状态栏，不额外占一行。应用身份仍由真实应用管理，演示切换角色不能宣称完成真实账号切换。

开箱流程：联网 → 家庭登录 → 选择角色 → 个人数字世界、我的数字大脑（AIChat）与日历。再次打开保留家庭演示状态，先选择使用者。

## 个人记忆与家庭分享

产品原则是“一人一份个人脑，家庭按授权共享”。家庭关系、付费权益、设备身份、个人数据访问权分别管理，不能用一个家庭账号让所有成员读取彼此全部资料。

人生几何当前本地实现已经走 我的数字大脑（AIChat） 既有工作空间接口保存原话和个人档案，未另外建立一份持久个人档案；本草案延续这一方向，不再为 Launcher 建立一套故事存储。[4] 哈奇的游戏进度继续由游戏保存，向个人脑提供学习摘要属于待实现的接口，不将全量游戏存档搬进 我的数字大脑（AIChat）。

切换成员时，需要停止录音、终止或隔离在途请求、卸载上一成员页面，并清理其可见会话与缓存。迟到的语音或模型回复仍归原成员，不能显示或保存到新成员。后台通知和桌面卡片也遵循当前成员权限。

家庭互动先采用“老人讲故事 → 老人选择分享 → 孩子阅读或提问 → 老人继续补充”的简单循环。私有内容默认不共享；管理员身份也不默认开放成年成员的私人谈话。分享撤回和权限闭环可用后才开放这条体验，不能用公开链接替代私有家庭分享。

## 技术复用与新增工作

已有 SilverMind 资料记录了 Android Home 原生壳、WebView 承载 H5、原生桥、设备激活和业务 App 更新的设计经验；OEM 规范还覆盖工厂写入设备身份、客户后续激活与绑定的职责划分。[5][6] 这些是复用起点，不能直接等同于 KeepWork 新产品已经可交付。

建议保留薄原生壳和 H5 桌面结构：原生负责 Home、必要系统能力、可信应用启动、本地兜底和恢复；H5 负责三个应用的入口、成员选择与展示。业务仍在各自项目迭代。首次样机先验证 H5 业务承载，只有经实测需要的能力才另加原生业务包。

| 类别 | 规划动作 | 验收依据 |
| --- | --- | --- |
| Launcher 经验 | 盘点可复用壳、桥、离线兜底与升级机制 | 实际代码、使用权限和真机演示 |
| KeepWork 自有产品 | 使用独立品牌、包名、签名、设备批次与发布配置 | 不与 SilverMind 客户环境串用 |
| 家庭身份 | 定义成员、管理员、设备与权益映射 | 三个应用识别同一当前成员，跨成员不可串读 |
| 应用接入 | 固定三个产品入口、登录交接与返回桌面行为 | 同一成员跨应用可连续使用，回桌面不丢状态 |
| 稳定性 | 本地可启动桌面、网络失败提示、升级失败恢复 | 断网和业务加载失败时仍能进入网络设置与恢复入口 |
| 设备交付 | 先验证正常安装，再验证 OEM 预装能力 | 静默更新等特权能力以 OEM 实机支持为准 |

本机未找到 wiki 所指的 `c:/lxzsrc/SilverMindLauncherApp/README.md`，因此本轮没有完成壳代码审计。正式估算工作量前需要定位当前仓库，确认能复用的代码与合作资产边界。

LifeStory 的 2026-10-12 实施记录仍标注本地、未发布；真实模型、麦克风、云同步及相册上传等线上能力不能由离线联调结果代替验收。[4] 样机必须选定相互兼容的真实发布版本。

## 硬件定义

先用现有 Android 样机验证三应用与共享使用，再冻结整机方案。关键要求是老人能看清和听清、儿童语言练习收音清楚、哈奇目标场景运行流畅、桌面和业务切换稳定，并方便桌面支架使用。

硬件测试覆盖屏幕和触控、麦克风与扬声器、WebView 兼容性、图形性能、持续使用温升、电池与待机恢复。云端语音作为首轮测试路径，本地模型不是一期前提。是否增加蜂窝联网，根据家庭试点中配网失败和使用地点决定。

芯片、内存、屏幕尺寸、BOM、售价与订货量暂不冻结。SilverMind 旧方案中的成本和硬件选择不直接转用：本产品多了哈奇语言情境和双成员切换，须重新实测。

## 国内与出海路径

共用 Launcher 与三应用产品结构，将界面语言、学习目标语言、语音、内容、模型服务、账号、支付和客服配置分开。界面语言与正在学习的语言必须可以不同。

国内先验证雄安可组织的家庭试点；海外首轮只选一个明确市场和语言组合。选择依据为已有可触达家庭、实际服务可用性及可支持的交付渠道，不预设“翻译成英文即完成出海”。

首发国家、当地儿童与个人数据要求、支付退款、硬件认证及服务部署条件，在确定市场后单独核验；本稿不作地区法规结论。国内与海外可以分别定价和交付，但保持统一的产品核心与数据模型。

## 收费结构与试点验证

建议先验证“硬件加明确期限的家庭服务”，再决定是否提供儿童、老人单场景套餐。权益应写明成员数、AI 用量、存储和到期行为；已有个人资料的访问与导出不应因 AI 额度耗尽而一并失效。这些均为待验证的产品规则，不能假设当前会员系统已支持。

试点分别记录硬件交付成本、模型与语音消耗、存储、售后投入和实际续费意愿，再测算价格。不要把儿童和老人的使用量合并后判断两个场景都成立。

建议用 10—20 个家庭开展连续四周探索，规模和周期为试验建议。关注：

- 开箱：是否在少量协助下完成首个成果，失败集中在哪一步。
- 儿童：每周主动回访、完成的语言情境，以及是否能独立复述或使用所练表达。
- 老人：每周主动讲述、回看与补充，是否愿意继续记录。
- 共用：两类成员是否持续使用、抢占设备的频次、切换出错和求助次数。
- 付费：购买者为何愿意付费、为何不愿续费，实际服务成本是否可承受。

观察时区分主动使用与工作人员催促使用；停留时间和游戏时长不单独视作学习效果。是否扩大投放，应依据分人群留存、服务成本和付费证据共同决定。

## 实施顺序与交付门槛

| 阶段 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| 范围与资产确认 | 三应用版本清单、Launcher 代码盘点、成员与权益方案、样机清单 | 确认可复用资产，定位关键接口缺口，明确首发试点组织者 |
| 单机样板 | 一个 Launcher、三个入口、儿童与老人配置切换 | 真机完整演示儿童语言练习和老人故事保存回看；数据隔离通过 |
| 家庭试点 | 开箱流程、使用记录、客服反馈、升级与恢复 | 获取分人群主动使用和家庭共用证据；解决主要稳定性问题 |
| 产品化与海外试点 | OEM 交付、订阅权益、一个海外市场配置 | 真实服务、地区要求、成本与售后条件均可验收 |

样机重点验证六件事：冷启动进桌面；三应用能打开并返回；语音和记录可保存；切换成员不串数据；断网可恢复；升级失败可回到可用版本。

最先需要明确的四项为：魔法哈奇首版接哪个版本；首批购买者从哪个渠道来；第一海外市场与语言组合；Launcher 现有代码位置及维护人。研发估算在这四项和真机基线确认后给出。
