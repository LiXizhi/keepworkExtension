# 小米蓝牙遥控器控制 Bumi 四向移动方案

本方案适用于 `apps/aichat-rust` 的 macOS 和 Windows 桌面客户端。每次在「Bumi 机器人」窗口开启遥控时，左右键默认控制转向。松开方向键，单按菜单键可切到平移，左右键分别控制左移、右移，再按一次菜单键切回转向。两种模式下，上下键都控制前进、后退，松开方向键即请求停止。方向以机器人自身为准。目标遥控器的按键上报、机器人的实际转向和侧移、失联后的停步时间均待实机验收。

## 使用步骤

1. 在 macOS 或 Windows 蓝牙设置中配对一只小米 RC003，打开「视图 → Bumi 机器人…」。点「检查按键」，分别按下、松开四个方向键与菜单键，核对窗口显示的键名。macOS 若提示缺少权限，在「系统设置 → 隐私与安全性 → 输入监控」中允许实际运行桌面端的应用，再重新开启检查。点「结束检查」退出。这一步可以在机器人关机时完成。
2. 连接 Bumi，确认它已在平坦空地上站稳，再选择行走或全身行走。点「开启方向键遥控」。窗口会重新读取机器人状态，状态码与所选步态一致后才能驱动。遥控框打开后会拦截送入控制窗口的按键。
3. 松开全部按键，按左、右键试转向。松手后单按菜单键，确认遥控框显示「平移」，再按左、右键试侧移。长按菜单键只切换一次。四个方向键的固定指令幅度均为 80，满幅为 127。
4. 说「停止」会请求停止移动并取消当前任务。从桌面端 0.2.276 起，停稳并松开方向键后，可在当前遥控框按住语音键继续说下一句。点「关闭遥控」会请求停止并收起遥控框。若切到其他窗口、遥控超时或蓝牙通信故障，框内会显示暂停原因。此时点「返回控制面板」，检查连接和机器人状态后重新开启遥控。

## 用语音键执行动作和导航

先到「编辑 → 遥控器语音输入…」确认小米 RC003 已就绪。回到 Bumi 窗口，连接机器人、选择步态，开启方向键遥控。保持遥控框在前台。按住语音键说一句，松开后由这个窗口接收最终识别结果。

- **走一步或转一下**。桌面端 0.2.274 加入单次点动口令。松开方向键，按住语音键说「向前走一步」「后退一步」「向左移一步」「向右移一步」「向左转一下」或「向右转一下」，每次任选一句。方向以机身为准，侧移和转向直接按口令执行，无需切换菜单键模式。在行走模式下，前进、后退、左转或右转使用「课堂点动档位」。默认标准档的摇杆幅度为 64/127，在 0.8 秒内按 100 毫秒节拍刷新，到时请求停止。侧移和全身行走模式下的语音点动仍约 0.4 秒。正常点动结束后遥控保持开启，等机器人停稳即可说下一句。实际位移和转角随步态、固件与地面条件而变。
- **连续走几步**。按住语音键说「向后走两步」或「向前走三步」，松开后开始。开启教室摄像头并填好这一方向的实测步幅即可使用 2 至 10 步的口令。每步停稳后拍一张新图，和迈步前的位置比较，确认实际位移。还有剩余步数时，用这张图检查下一步的地面。说「停下来」可取消剩余步数。
- **连续做动作**。松开方向键，按住语音键说「挥手」，松开即可发送。看到机器人做完动作并站稳，再按住语音键说「握手」。也可以说「欢呼」或「跳舞」。从 0.2.276 起，这些口令可以在同一次遥控中逐句发出。使用较早的桌面端时，按窗口提示重新选择步态并开启遥控。
- **动作后继续走**。姿态动作会清除之前的行走步态。等机器人站稳，在同一遥控框说「进入行走模式」或「进入全身行走模式」。待窗口确认机器人已进入所选步态，再说「向前走一步」或按方向键移动。
- **看目标或走到目标旁。** 在「课堂摄像头与语音」开启对准地面的固定摄像头。按住遥控器语音键说「看看垃圾桶」，松开后可核对摄像头中的目标标记。需要移动时，在行走模式说「走到垃圾桶旁边」。窗口会从机器人自身朝向判断方位，每次点动停稳后重新观察。现场也可以说「停下来」中断任务。[课堂操作与标定](bumi-camera-vision-navigation.md)

## 按键接收

小米遥控器与电脑配对，电脑通过 BLE 连接用户选定的 Bumi。用户确认机器人已站稳，查询状态确认已进入行走模式，再开启「方向键遥控」。启用时须先确认方向键和菜单键均已释放，避免把启用前按住的键当作新指令。

复用已有的原生按键监听。macOS 通过 IOHID 获取按键的来源设备和 HID usage，Windows 通过 Raw Input 获取来源设备和虚拟键码。将所选遥控器连续两次上报的按键集合做差，识别四个方向键及菜单键的按下和释放。相同状态的重复上报不触发新动作。方向控制独立于语音识别，仅在 Bumi 窗口处于前台且遥控已启用时消费方向键。普通键盘、其他遥控器或来源无法确定的事件均不驱动机器人。[macOS 按键识别](../apps/aichat-rust/src-tauri/src/remote_voice/buttons_macos.m) · [Windows 按键识别](../apps/aichat-rust/src-tauri/src/remote_voice/home_windows.rs)

## 运动指令与停止

本地接口 `bumi_control` 的 `move` 指令在 `vx` 和 `vyaw` 之外接受可选的 `vy`，缺省值为零。原有摇杆、转向按钮和语音请求可继续使用。遥控发出的非零运动请求携带本次捕获的 `remoteCaptureId`，通过当前控制窗口拥有的 BLE 连接发送。[协议与移动帧](bumi-ble-control.md) · [Rust 编码器](../apps/aichat-rust/src-tauri/src/app/bumi/protocol.rs)

下表按 BLE 操作码 `0x13` 后的三个速度字节排列。屏幕上的「转向 / 侧移」选择同时控制摇杆的水平拖动和左右点动按钮。遥控器有独立的转向 / 平移模式，单按菜单键只切换模式。

| 遥控器输入 | 预期动作 | 纵向 `vx` | 转向 `vyaw` | 侧向 `vy` |
| --- | --- | ---: | ---: | ---: |
| 上 | 前进 | +80 | 0 | 0 |
| 下 | 后退 | −80 | 0 | 0 |
| 左（转向） | 左转 | 0 | +80 | 0 |
| 右（转向） | 右转 | 0 | −80 | 0 |
| 左（平移） | 左移 | 0 | 0 | +80 |
| 右（平移） | 右移 | 0 | 0 | −80 |
| 松开方向键 | 停止 | 0 | 0 | 0 |

- **单独按住一个方向键**时立即发出第一帧，随后复用移动控制器的 100 毫秒刷新周期。同一时间最多写入一帧，上一帧尚未完成时跳过本次刷新。
- **松键、双键冲突、窗口失焦、关闭窗口或遥控器掉线**时取消后续移动，优先发送零速度。若有一帧正在写入，完成后下一帧即为停止帧。行走时按下菜单键也会请求停止。遇到组合按键时，先松开菜单键和全部方向键，再单独按所需按键。
- **机器人链路中断**时清除按键状态和待发指令，提示「停止状态未知」。重连后须重新启用并重新按键。

## 实施前需确认

| 项目 | 现场记录与确认内容 |
| --- | --- |
| 小米遥控器 | 背面型号、系统配对名称和 HID 设备标识。仓库已有 RC003 的识别逻辑，需核对手头设备，并记录方向键与菜单键各自按下和释放时的原始键值。 |
| 控制电脑 | macOS 或 Windows 版本、蓝牙与输入监听权限。两台蓝牙设备同时连接时，确认仍可唯一识别所选遥控器。 |
| Bumi 机器人 | 铭牌型号、标准版或教育版、固件版本、BLE 广播名称和测试步态。核对 GATT 写入与通知特征，确认能查询机器人当前状态。[GATT 配置](bumi-ble-control.md#32-gatt-配置) |
| 运动接口 | 确认固件接受三轴移动帧、纵向、转向与侧移轴的幅值和符号、零速度帧的停步表现，以及 BLE 中断后固件能否自行停步和所需时间。 |

## 四向映射验收

1. **只验输入。** 在不驱动机器人的诊断模式下，依次短按、长按并释放方向键与菜单键，记录来源设备、原始键值和键名。每次松手后按键集合应为空。用普通键盘或另一只遥控器重复操作，Bumi 窗口应收到零条运动请求。
2. **核对指令。** 用模拟 BLE 接收端记录每个方向从按下到释放的完整序列，按上表逐轴比对。转向时左、右键仅改变第二个速度字节，平移时仅改变第三个。左、右分别为 `50` 和 `B0`（十六进制）。单独长按菜单键应只切换一次，期间应无非零速度帧。插入延迟写入、双键、失焦和断连事件，核对取消后的写入顺序，确保停止帧后无旧移动帧，重连后无动作重放。
3. **真机验收。** 在平坦空旷的地面标出十字线和机头朝向。确认站稳后逐键低速短按，每个方向重复三次。记录实际位移方向、机头朝向和松键至停稳的时间。前后键应产生对应的纵向位移。转向时左右键应使机头分别向左、向右转，平移时左右键应使机器人保持朝向向左、向右移动。
4. **验证失联。** 分别验证遥控器掉线和机器人 BLE 中断，记录现场停步表现与界面提示。将结果与型号、固件、步态一起保存，区分电脑发出停止帧的时间和机器人实际停稳的时间。
5. **验证语音点动（待实机验收）。** 先说「向前走一步」，确认机器人相对机头前进一次并自动停稳。逐一验证其余五个口令，记录识别文字、实际位移或转角，以及写出停止帧至停稳的时间。说「不要向前走一步」应保持静止。再用只读识别核对带拍摄时间的画面。
