# 小米蓝牙遥控器控制 Bumi 四向移动方案

本方案适用于 `apps/aichat-rust` 的 macOS 和 Windows 桌面客户端。用户在「Bumi 机器人」窗口开启遥控后，按上、下键控制前进、后退，按左、右键控制左转、右转，松手即请求停止。方向以机器人自身为准。目标遥控器的按键上报、机器人的实际转向和失联后的停步时间均待实机验收。

## 第一版使用步骤

1. 在 macOS 或 Windows 蓝牙设置中配对一只小米 RC003，打开「视图 → Bumi 机器人…」。点「检查按键」，分别按下、松开四个键，核对窗口显示的方向。macOS 若提示缺少权限，在「系统设置 → 隐私与安全性 → 输入监控」中允许实际运行桌面端的应用，再重新开启检查。点「结束检查」退出。这一步可以在机器人关机时完成。
2. 连接 Bumi，确认它已在平坦空地上站稳，再选择行走或全身行走。点「开启方向键遥控」。窗口会重新读取机器人状态，状态码与所选步态一致后才能驱动。遥控框打开后会拦截送入控制窗口的按键。
3. 松开全部方向键，再逐个按住上、下、左、右键。四个键的固定指令幅度均为 80，满幅为 127。
4. 点遥控框中的「关闭遥控」结束并请求停止。切到另一窗口或连接中断也会结束本次遥控，再次使用须手动开启。

## 对着遥控器说「跳舞」或「走到讲台」

在 Tauri 桌面开发版 0.2.259 中，先到「编辑 → 遥控器语音输入…」确认小米 RC003 已就绪。回到 Bumi 窗口，连接机器人、选择步态，开启方向键遥控。保持遥控框在前台。按住语音键说一句，松开后由这个窗口接收最终识别结果。

- **试跳舞**。让机器人周围留有动作空间，松开方向键说「跳舞」。窗口会显示舞蹈指令的写入结果。动作会清除步态选择，下一次行走前需等机器人站稳、重新选步态并开启遥控。
- **试规划**。在「场地地图与目的地」把现场划成方格。选好步态后，标记机器人当前格与朝向、沿途可通行的格子，并把讲台旁可停靠的格子命名为「讲台」。开启遥控，说「走到讲台」。系统只通过标明可通行的相邻格子规划路线，未标格和障碍格都绕开。没有通路、位置或目标时，面板会提示缺少哪项。
- **沿路线走**。说「执行本段」，Bumi 会根据路线短促左转、右转或前进，约 0.4 秒后请求停止。还未到位可以重复，也可以在面板按住本段按钮微调，松手请求停止。看到朝向对准、或机器人到达下一格并停稳后，说「已到位」。只有这次现场确认才推进路线。途中说「停止」或关闭遥控即可停止移动并取消路线。

格子的大小按现场通行空间确定。地图保存在本机，机器人位姿来自操作者观察。现有 BLE 协议报告步态和运行状态，没有接入教室相机定位、实时避障或自主到点反馈。人或障碍物改变通道时，应先停止、更新地图，再从实际位置规划。

## 按键接收

小米遥控器与电脑配对，电脑通过 BLE 连接用户选定的 Bumi。用户确认机器人已站稳，查询状态确认已进入行走模式，再开启「方向键遥控」。启用时须先确认四键均已释放，避免把启用前按住的键当作新指令。

复用已有的原生按键监听。macOS 通过 IOHID 获取按键的来源设备和 HID usage，Windows 通过 Raw Input 获取来源设备和虚拟键码。将所选遥控器连续两次上报的按键集合做差，识别 `up`、`down`、`left`、`right` 的按下和释放。相同状态的重复上报不触发新动作。方向控制独立于语音识别，仅在 Bumi 窗口处于前台且遥控已启用时消费方向键。普通键盘、其他遥控器或来源无法确定的事件均不驱动机器人。[macOS 按键识别](../apps/aichat-rust/src-tauri/src/remote_voice/buttons_macos.m) · [Windows 按键识别](../apps/aichat-rust/src-tauri/src/remote_voice/home_windows.rs)

## 运动指令与停止

本地接口 `bumi_control` 的 `move` 指令在 `vx` 和 `vyaw` 之外接受可选的 `vy`，缺省值为零。原有摇杆、转向按钮和语音请求可继续使用。遥控发出的非零运动请求携带本次捕获的 `remoteCaptureId`，通过当前控制窗口拥有的 BLE 连接发送。[协议与移动帧](bumi-ble-control.md) · [Rust 编码器](../apps/aichat-rust/src-tauri/src/app/bumi/protocol.rs)

下表按 BLE 操作码 `0x13` 后的三个速度字节排列。屏幕上的「转向 / 侧移」选择同时控制摇杆的水平拖动和左右点动按钮。遥控器左右键始终控制转向。

| 遥控器输入 | 预期动作 | 纵向 `vx` | 转向 `vyaw` | 侧向 `vy` |
| --- | --- | ---: | ---: | ---: |
| 上 | 前进 | +80 | 0 | 0 |
| 下 | 后退 | −80 | 0 | 0 |
| 左 | 左转 | 0 | +80 | 0 |
| 右 | 右转 | 0 | −80 | 0 |
| 松开 | 停止 | 0 | 0 | 0 |

- **按住单键**时立即发出第一帧，随后复用移动控制器的 100 毫秒刷新周期。同一时间最多写入一帧，上一帧尚未完成时跳过本次刷新。
- **松键、双键冲突、窗口失焦、关闭窗口或遥控器掉线**时取消后续移动，优先发送零速度。若有一帧正在写入，完成后下一帧即为停止帧。双键冲突后等全部方向键释放，再接受下一次按下。
- **机器人链路中断**时清除按键状态和待发指令，提示「停止状态未知」。重连后须重新启用并重新按键。

## 实施前需确认

| 项目 | 现场记录与确认内容 |
| --- | --- |
| 小米遥控器 | 背面型号、系统配对名称和 HID 设备标识。仓库已有 RC003 的识别逻辑，需核对手头设备，并记录四键各自按下和释放时的原始键值。 |
| 控制电脑 | macOS 或 Windows 版本、蓝牙与输入监听权限。两台蓝牙设备同时连接时，确认仍可唯一识别所选遥控器。 |
| Bumi 机器人 | 铭牌型号、标准版或教育版、固件版本、BLE 广播名称和测试步态。核对 GATT 写入与通知特征，确认能查询机器人当前状态。[GATT 配置](bumi-ble-control.md#32-gatt-配置) |
| 运动接口 | 确认固件接受三轴移动帧、纵向与转向轴的幅值和符号、零速度帧的停步表现，以及 BLE 中断后固件能否自行停步和所需时间。 |

## 四向映射验收

1. **只验输入。** 在不驱动机器人的诊断模式下，依次短按、长按并释放四键，记录来源设备、原始键值和归一化方向。每次松手后方向键集合应为空。用普通键盘或另一只遥控器重复操作，Bumi 窗口应收到零条运动请求。
2. **核对指令。** 用模拟 BLE 接收端记录每个方向从按下到释放的完整序列，按上表逐轴比对。左、右键应仅改变第二个速度字节，分别为 `50` 和 `B0`（十六进制）。插入延迟写入、双键、失焦和断连事件，核对取消后的写入顺序，确保停止帧后无旧移动帧，重连后无动作重放。
3. **真机验收。** 在平坦空旷的地面标出十字线和机头朝向。确认站稳后逐键低速短按，每个方向重复三次。记录实际位移方向、机头朝向和松键至停稳的时间。前后键应产生对应的纵向位移，左右键应使机头分别向左、向右转。
4. **验证失联。** 分别验证遥控器掉线和机器人 BLE 中断，记录现场停步表现与界面提示。将结果与型号、固件、步态一起保存，区分电脑发出停止帧的时间和机器人实际停稳的时间。
