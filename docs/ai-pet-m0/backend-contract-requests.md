## Integration handoff rule

Replace development fixtures with adapters only after mapping conceptual semantics to a verified canonical contract. Record deliberate differences and negotiate incompatible capability versions. Retain unknown optional fields where appropriate; never weaken authorization to accommodate older clients. A timeout after a mutation means an uncertain outcome, not permission to retry under a new request ID. Import and deletion must never use the model-inference path.

The evidence ledger is [readiness.md](readiness.md); execution and fault cases are [verification.md](verification.md).

## Slice 2 clarification: offline persistence is not service authority

A local reducer/journal or durable widget snapshot does not resolve BC-01/03/05/06. Service owners still must supply authenticated account-region selection, immutable ordered event semantics, definitive request-outcome lookup, source/message deletion identity mapping and retention guarantees. Offline tests can demonstrate deterministic recovery, local tombstone suppression and account-safe presentation; they cannot establish server acceptance, cross-device convergence, deletion from backups/providers, or authorize replay of an uncertain request. Development tooling/APK/Xcode evidence likewise does not close any backend contract request.

Slice 3 compact checkpoints do not close BC-03/06: the service must supply trustworthy message/request/source mappings, including deletion arriving before append acceptance. A source tombstone alone cannot identify an unrelated pending command; local text can be scrubbed once the authoritative mapping arrives. Replacing a serialized checkpoint removes known deleted payload from that representation only. Old journals, prior checkpoint copies, backups and provider data require separately verified disposal/retention handling; a caller-recomputable digest supplies neither authorization nor rollback protection.
